# Cerberus licensing: free personal use, paid commercial / heavy production

Cerberus is **source-available, not OSI open-source** under its current LICENSE. The license text is controlling; this page is a plain-language explanation, not a replacement.

| Scenario | License |
| --- | --- |
| Individual's personal notes, saved links, local hobby project | Free personal use (within the heavy-use thresholds) |
| Personal learning, experimenting with the desktop pet | Free personal use |
| Individually modifying the code for noncommercial personal use | Free personal use |
| Freelance work, paid consulting, workplace usage or a business | Separate paid written license required |
| Running Cerberus as part of a commercial product or service | Separate paid written license required |
| More than 10,000 newly stored items in any rolling 30-day period | Separate paid written license required |
| More than 10 GiB of newly ingested attachment data in any rolling 30-day period | Separate paid written license required |
| Shared/multi-user or centralized unattended ingestion | Separate paid written license required |

**Do not confuse a public GitHub repository with unrestricted open source.** Under this model you can inspect and fork, but commercial/production rights are not granted by default. Personal use stays free as described in LICENSE. Pricing and the commercial agreement have NOT been set up yet; opening the app does not charge anyone, and no payment or activation mechanism currently exists.

## How to request a paid license

Request a written commercial agreement from the repository owner, iAlirezaaa, using contact details they publish on their GitHub profile. Explain organizational size/users, deployment, expected capture volume, redistribution plans, support/security requirements and requested term. Do not send proprietary data or secrets in a public issue. No specific price, licensing platform, automatic invoicing or support SLA has been promised.

## Previously published MIT revisions

Initial revisions of Cerberus were distributed under MIT. Those historical MIT rights **cannot be revoked retroactively** for copies already released under MIT. The new terms are prospective and only to the extent the copyright holder(s) can license that material. Code derived from earlier MIT-licensed revisions may remain usable under MIT according to the applicable grant. Third-party packages keep their own licenses.

If the goal is enforceable paid licensing for future exclusive functionality, preserve provenance and contribution rights, and consider separating genuinely new proprietary features into controlled modules. The project owner should have a lawyer review this custom license before charging customers.

## For agents/contributors

Do not change, remove or bypass license notices. Do not automatically install telemetry, activation checks or payment services. Do not label this repository "MIT", "GPL", "Apache", "free for business", or "open source" in metadata or documentation. When modifying code that predates the license switch, preserve historical licensing rights.
